# Project architecture rules

- WhatsApp shopping trials authenticate the existing store owner, query live store-scoped stock, and return only public catalog fields; trials never send messages or mutate orders, and are not evidence that a Meta catalog or inbound bot is connected.
- New shopping AI calls use the request-local Responses SDK and shared run-ID helpers, strict structured output, no automatic retries, and no timer aborts; live inventory, not AI-generated data, supplies pictures, prices and variants.

- Dashboard weekly sales use complete Asia/Kolkata calendar days with paged queries and the same paid-order cancellation filter as headline totals; the first day must not start at the current clock time.

- Generate WhatsApp template review examples only for actual body variables; static invites must not require customer-name placeholders.

- Product-video imports process the original video locally, clean selected frames server-side, retain only final inventory photos, and always delete temporary frames; this preserves credentials, tenant isolation, and storage hygiene.
- Product recognition resolves only the caller's store-scoped media URLs and sends downloaded image bytes inline to AI; this avoids provider URL-fetch timeouts without broadening storage access.
- Long video recognition starts an opt-in JSON keep-alive response before frame downloads and preserves terminal error status in the payload; this prevents silent browser connection timeouts without duplicating billed AI work.
- Keep the admin main flex column shrinkable and inventory row actions pinned above horizontally scrolling cells; this keeps authorized touch controls reachable on tablets.
- Sitemap is generated by `scripts/generate-sitemap.ts` (wired to `predev`/`prebuild`) writing `public/sitemap.xml`; keep its category entries in sync with the home-page category tiles when categories change.
- Mark invoice free-text remark fields with `data-scanner-ignore` and reset scanner bursts when they receive keys; typing speed must never erase customer notes.

- Storefront URLs are readable slugs via `src/lib/seoUrls.ts`: products `/product/<slug>-<uuid>` (id parsed from the tail so old links work), categories `/category/<slug>` matched by slug; keeps links SEO-friendly without breaking shared URLs.

- Reports show Purchases as an informational line only; profit uses cost of goods sold from batch buying prices, so purchases are never deducted (avoids double counting).
- Purchase bill scanning uses the `scan-purchase-bill` function (owner or can_purchases only) with @lovable.dev/ai-gateway; extracted fields only prefill the form and the user must review before saving.
